科研项目信息化管理平台 — 目标机部署步骤
日期：2026-08-21

一、目标机前提
1. Linux x86_64，已安装 Docker。
2. 表单维护工具已在本机运行，默认容器名 form-maintenance-8092，端口 8092。
3. 本平台将占用端口 18087。若被占用，改 .env 里 SRPM_PORT 后再装。
4. 不要动 8092 的数据卷（常见名 fm8092-data）。不要 docker compose down -v。

二、上传
把整个「SRPM-目标机部署包」目录拷到目标机，例如：
  scp -r "SRPM-目标机部署包" user@目标机:/opt/srpm
或用 U 盘拷到 /opt/srpm。

三、安装平台（不含演示项目）
  cd /opt/srpm
  chmod +x *.sh
  test -f .env || cp .env.example .env
  sudo bash ./install.sh

完成后：
- 容器 srpm-18087 在跑
- 数据在 Docker 卷 platform_srpm-data
- 已有 7 个单位、渠道字典、12 个可登录账户
- 项目表为空，表单台账尚未接入

四、接入本机 8092 表单库（必须做）
原则：只导出台账行，写入本平台 srpm.db 的 kv 键 transition.records.v19。
禁止把 8092 的 platform.db 整库拷进 18087。

  sudo bash ./attach-form-ledger.sh

若 8092 容器名不是 form-maintenance-8092：
  sudo FORM_CONTAINER=实际容器名 bash ./attach-form-ledger.sh

脚本会：只读导出 8092 行 → 写入 18087 → 清演示项目 → 保留 12 个账户。
8092 容器不重启、数据卷不改。

五、验收
  sudo bash ./verify.sh

浏览器：

七、禁止事项
- docker compose down -v
- docker volume rm platform_srpm-data（有业务数据时）
- 合并 sqlite 文件（platform.db 与 srpm.db 不是同一套库）
- 停 8092、改 8092 卷、两边同时改同一张表单

八、卸载（仅空跑测试时）
先停平台，不要带 -v：
  docker stop srpm-18087 && docker rm srpm-18087
有确认要扔掉平台库时才：
  docker volume rm platform_srpm-data
8092 始终不要删。
